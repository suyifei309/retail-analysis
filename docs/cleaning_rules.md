# 数据清洗规则表

> 原则：每条规则必须记录 **做了什么 / 为什么 / 影响多少行**。这张表就是面试时讲"数据清洗"的底稿。
> 状态列：☐ 待处理 → ☑ 已处理（由 01_clean.ipynb 自动回填影响行数）

| # | 问题 | 规则 | 原因 | 影响行数 | 状态 |
|---|------|------|------|----------|------|
| 0 | Excel 文本列混型（Invoice 混有 int 单号与 'C' 退货单号；Description 混有纯数字描述） | 下载时统一转 string 类型（get_data.py） | 混型 object 列无法写 parquet | 全表 8 列中的 5 列 | ☑ |
| 1 | 退货单（Invoice 以 "C" 开头） | 拆分为独立退货表，用于退货率分析，不与正常交易混算 | 退货是业务信号，不是噪音 | 19,494（1.8%） | ☑ |
| 2 | 非退货单 Quantity ≤ 0 | 剔除 | 无业务含义的负值 | 3,457 | ☑ |
| 3 | 非退货单 Price ≤ 0 | 剔除 | 无业务含义的零/负价（多为调账行） | 6,207 | ☑ |
| 4 | Customer_ID 缺失 | 交易表保留 + `has_customer` 标记；客户维度分析（RFM/流失）时剔除 | 无客户的交易是真实销售额（贡献 14.8% GMV），删掉会低估总量 | 242,257（23.1% 行 / 14.8% 销售额） | ☑ |
| 5 | 完全重复行 | 剔除 | 重复入库会双计金额 | 33,945（3.24%） | ☑ |
| 6 | 非商品交易（StockCode 不含数字：邮费/手工调账/样品） | 保留 + `is_product` 标记 | 是真实收入但会污染商品/购物篮分析 | 4,382（3.30% 销售额） | ☑ |

> 注：规则 2/3/5 的行数有重叠（重复行同时也是零价行的部分），去重后实际剔除 39,964 行。
> 长尾极值**不删**（如单笔 168,470 英镑、单笔数量 80,995 的批发大单），分析时用分位数/对数轴处理。
